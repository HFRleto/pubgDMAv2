2. DETAIL DES CHANGEMENTS
-------------------------

2.1  Media.vcxproj : compilation en UTF-8
     Dans les deux lignes <AdditionalOptions>, ajout de /utf-8 :
       <AdditionalOptions>/utf-8 /FS /bigobj %(AdditionalOptions)</AdditionalOptions>
       <AdditionalOptions>/utf-8 /FS %(AdditionalOptions)</AdditionalOptions>
     Raison : sans cette option, sur un Windows non chinois, les textes chinois du
     code (noms d'images, noms d'objets) sont convertis en "?" a la compilation.

2.2  Source\Overlay\Texture.cpp : plantage au demarrage (CORRECTIF PRINCIPAL)
     Symptome : la console s'affiche puis tout se ferme au bout de quelques secondes
     (exception 0xc0000409 dans le journal d'evenements Windows).
     Cause : Texture::LoadTextures ecrivait le chemin de chaque image dans un flux
     ("ss << file"), ce qui leve une exception sur les fichiers au nom chinois quand
     Windows n'est pas en chinois.
     Correctif :
       - en tete du fichier, apres "#define STB_IMAGE_IMPLEMENTATION" :
             #define STBI_WINDOWS_UTF8
       - la boucle de LoadTextures utilise file.path().generic_u8string() pour
         construire la cle, et l'extension est prise apres le dernier point.

2.3  Source\Hack\Items.h : corruption memoire dans l'inventaire
     Vers la ligne 64, dans GetWeaponAttachedItems :
       avant : (uint64_t*)&Item.second.Count
       apres : (int*)&Item.second.Count
     Raison : Count est un int (4 octets) ; la lecture de 8 octets debordait du bloc
     alloue. Bug du code d'origine, independant des offsets.

2.4  Source\Hack\Decrypt.cpp : fonction Decrypt::CIndex
       DWORD Decrypt::CIndex(DWORD value)
       {
           if (!value)
               return 0;

           return ((value << 9) & 0xFFFF0000) ^
               _rotr(value ^ 0xD286E6F2, 7) ^ 0x4CC9D1B1;
       }
     Source : offsetTest.txt, confirme par le script DMA (CIndexHi).

2.5  Source\Common\Offset.h : offsets mis a jour
     Fichier a copier tel quel. Ce qui a ete fait :
       - commentaires chinois traduits en francais ;
       - 58 entrees de la map jamais lues par le programme mises en commentaire,
         avec leurs constantes, marquees "// inutilise" ;
       - valeurs passees en 2609, la source etant notee sur chaque ligne :
             // 2609 : SDK          trouve dans le dump SDK
             // 2609 : offsetTest   premier fichier texte
             // 2609 : script       script DMA (tools\dumper.py)
             // 2609 : NamesDump    indice de nom (MouseX, MouseY)

       - cles ajoutees a la map car lues par le code mais jamais enregistrees :

       - constante ajoutee : GObjectsCount.
     Etat : 159 cles lues par le programme ; 129 a jour, 13 a verifier,

3. LIRE LA CONSOLE
------------------

  [OFFSET]     offsets charges au demarrage
  [DMA]        etat de la carte DMA
  [PROCESSUS]  jeu detecte, PID et adresse de base
  [SCENE]      changements de scene (RechercheProcessus / Lobby / EnPartie) et carte
  [CHAINE]     valeur de chaque pointeur ; "(INVALIDE)" designe l'offset a corriger
  [ETAT]       entites, joueurs, carte, champ de vision ; toutes les 10 s en partie

Etat constate en jeu (terrain d'entrainement Range_Main) :
  - chaine valide de UWorld jusqu'a la camera ; environ 1470 entites, 15 joueurs ;
  - GameState INVALIDE : la valeur 0x278 est fausse, c'est le seul maillon casse.


4. PREREQUIS SUR L'AUTRE PC
---------------------------

  Compilation : Visual Studio 2022, charge "Developpement Desktop en C++" (voir BUILD.md).
      MSBuild.exe "Jax Kane.sln" /p:Configuration=Release /p:Platform=x64 /m

  Script DMA (facultatif) : Python 3 en 64 bits, puis
      python -m pip install memprocfs iced-x86
      python tools\dumper.py --no-dump --json -o tools\dumper_out

  Debogage (facultatif) : cdb.exe, fourni avec les "Debugging Tools for Windows"
  du SDK Windows.
      powershell -ExecutionPolicy Bypass -File tools\debug_run.ps1 -Seconds 60

  Les chemins de MSBuild et de cdb sont ecrits en dur en tete de tools\debug_run.ps1 ;
  a adapter si Visual Studio n'est pas l'edition Community.
